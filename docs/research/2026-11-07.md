## 4. Techniques for open issues

- **#32 (VLAN CR -> NADs, node bridges):** a [Sylva issue](https://gitlab.com/sylva-projects/sylva-core/-/issues/1586) names the same gap: the Multus bridge plugin assumes the bridge already exists on every node, and declarative host bridge/VLAN setup usually leans on nmstate/NetworkManager. Common NAD patterns are macvlan on a VLAN sub-interface ([Talos guide](https://docs.siderolabs.com/kubernetes-guides/cni/multus), [ODF docs](https://docs.redhat.com/en/documentation/red_hat_openshift_data_foundation/4.18/html/managing_and_allocating_storage_resources/creating-multus-networks_rhodf)) and OVS-CNI with a `vlan` field ([KubeVirt](https://kubevirt.io//2018/attaching-to-multiple-networks.html)). Both need the interface name to match on every node, which supports the owner-decision framing (own agent DaemonSet vs node manifest). No change to the recommendation.
